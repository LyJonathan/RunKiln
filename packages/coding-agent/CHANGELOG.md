# Changelog

## [Unreleased]

- Setup v2: shorter and in dependency order. Key → Model (auto with a mode, or a manual model with its thinking level on the same screen) → Classifier only when auto routing or auto permissions need a key → Permissions → Theme → a compact Review → a Done screen with Alt+R, Alt+M and /help. One short line per screen, hints only on the focused option, defaults preselected so Enter, Enter, Enter finishes. The separate Thinking step is gone. Skipping the classifier no longer happens implicitly: `router.classifier` is only written when you pick it or Skip. Storage is unchanged.
- Images in the TUI: they were never attached. Ctrl+V wrote the clipboard image to a temp file and inserted its path as text, a dragged-in path stayed text, and the prompt went out without image content, so the model only saw a path. Now Ctrl+V (Alt+V on Windows), a pasted or dragged-in image path, and `@image.png` attach the image to the prompt, shown as a removable `[image 1 - 240 KB]` chip. Clipboard reads cover Wayland (`wl-paste`), X11 (`xclip`), WSL (PowerShell), macOS (helper, `pngpaste`, AppleScript) and Windows (helper, PowerShell), and say what to install when nothing can read the clipboard (it was silent). Images over 2 MB are resized; non-images and files over 30 MB are refused with a reason. A manual model without image input now gets a warning (interactive and print mode).

### Added

- Footer parts: every part of the footer has an on/off row in /settings > Footer (`footer.show`: cwd, branch, session, permissions, cost, cache, context, autoCompact, tests, xp, todo, queue, time, provider, router, model, thinking, decision, confidence, turn, statuses), plus presets All, None and Default. A row with every part off disappears. Footer item `queue`. Defaults unchanged; `footer.items` reads as before.
- `display.timestamps` `off|time|datetime`: a dim time under each user message and assistant reply, in `TZ` or the OS zone. Default off.
- /settings in sections (Model, Display, Turn summary, Changes, Footer, Editor, Images, Startup, Terminal). New options: `display.turnSummary` `reply|footer|off` (footer: the last turn as a footer row; booleans still read), `display.turnSummaryFields` (time, files, tools, cost, model, clock), `display.toolOutput` `collapsed|expanded`, `display.changesTrayPosition` `editor|footer`, `display.diffOpens` `review|git` (`/diff review` added), the review key (`app.changes.review`, saved to keybindings.json), prose width (`ui.maxProseWidth`) and a footer layout row. Footer item `turn`. Defaults unchanged.
- Changes tray: one row above the editor with the files the agent changed this session, `3 files  +27 -8   app.ts  +12 -3   +1 more`, hidden when nothing differs. Counts come from the /undo checkpoints (shell commands included). A click, Alt+C (`app.changes.review`) or `/diff` opens the review view: every changed file with its hunks, Up/Down per hunk, Left/Right per file, `k` keeps a hunk (it leaves the tray, the file stays), `r r` reverts it, `K` / `R R` do the whole file, Esc closes. `/diff git` shows the uncommitted changes as before. `display.changesTray: false` (or /settings) turns the tray off.
- `/setup`: the setup hub, one re-enterable screen with six sections as tabs: Keys (RunInfra, Jev, OpenRouter: set, test, remove; a key is saved once it checks out; RunInfra shows its model count and available credits), Model (auto or manual and thinking; Enabled models and Ctrl+P cycle open the existing screens), Routing (mode, classifier, OpenRouter decision model), Permissions, Look (theme with live preview) and Footer (opens the footer picker). `/setup <section>` and `runkiln setup <section>` open one section; `/setup wizard` reruns first-time setup. Rows, tabs and hints are clickable.
- `runkiln key [set|remove|test] [runinfra|jev|openrouter]` (`--stdin`, `--router-model <id>`): manage keys from the shell. `runkiln key` alone lists which keys are set and where they come from.
- A UI text lint test (`ui-text-style.test.ts`) fails on a middle dot or em dash in UI strings.
- Clickable UI in the full-screen view: approval and plan answers, the model, session, tree, rewind and message pickers, and footer items respond to clicks, with hover highlight and wheel selection. Tool cards show an action strip on hover (open, diff, copy path, copy cmd, rerun, `⋯`) and a right-click menu (copy output, revert file, rewind from here); revert file restores one file from the turn's checkpoint after asking. Clicked paths open in the editor through `editor.open` presets or a `{file}:{line}:{col}` template, or are copied over SSH.
- `mouse: on|wheel|off` (and `RUNKILN_MOUSE`), `mouseRightClick: auto|menu|paste`, `cardActions`, `terminal.pointerShape` (OSC 22 hand pointer) and `terminal.fullRepaint` (off by default). Windows Terminal: OSC 9;4 progress on by default, OSC 52 then `clip.exe` then PowerShell for copy, a Shift-select hint. Linux copies also fill PRIMARY.
- Standalone executables for win-x64, linux-x64, linux-arm64, darwin-arm64 and darwin-x64 (Node single executable applications, `npm run build:binaries`), attached to GitHub releases with `SHA256SUMS`. The first run unpacks RunKiln to the user cache folder; no Node install needed.
- Windows: the `bash` tool also finds per-user and Scoop Git installs and the Git that owns `git.exe` on PATH, prefers MSYS2/Cygwin bash on PATH over WSL's `System32\bash.exe` (it took the first `where` match, often WSL), and skips the WindowsApps WSL stub. With no bash at all, `powershell` replaces `bash` in the default tools. Repo map focus paths and `/hooks` paths now work with `C:\` paths, and a CRLF `.git/info/exclude` no longer gets duplicate entries.
- npm packages ship without source maps (coding-agent tarball 4.7 MB to 3.1 MB), declare `os` (win32, linux, darwin), and the `runkiln` bin prints a clear message on Node older than 22.19 instead of a SyntaxError.
- Approval prompts show what you approve: a write or edit shows its diff (`computeEditsDiff` for edit, the file on disk against the new content for write, the whole file for a new one), collapsed to 8 lines with `+a −r` in the title and the expand key for the rest, including writes outside the project (path-only before). Shell commands are shown whole with syntax colour; MCP calls show their arguments as compact JSON. The prompt fits short terminals (80x24) by cutting the diff and hints further.
- `permissions.promptTimeoutSec` (default 0: wait for the answer; it was a fixed 120 s auto-deny) and `permissions.timeoutAction: "deny" | "pause"`. Pause keeps the prompt open and sends a notification.
- Plan approval: `e` opens the plan in `$VISUAL`/`$EDITOR` (or `externalEditor`), and the edited plan is what gets approved and sent to the agent.
- Configurable footer: `footer.items` (model, router, thinking, permissions, cost, cache, context, tests, jobs, todo, branch, cwd, session, time, and `break` for a new line), drawn in order with the lowest-priority items dropped on narrow terminals and the permission badge never dropped. Unset, the footer renders byte for byte as before (golden test over 28 scenarios × 10 widths). `/setup footer` (old name `/statusline`) picks, reorders and saves the items with a live preview.
- Dynamic terminal title `RunKiln - <project> - ● working / ✓ done / ⚠ needs approval` (OSC 0/2 and tmux pane titles; the previous title is restored on exit). `terminal.dynamicTitle: false` keeps it static.
- Accessibility: `NO_COLOR` turns theme colours off; `ui.reducedMotion` replaces spinners and animations with static indicators; new `dark-colorblind`, `light-colorblind` and `high-contrast` themes; `ui.maxProseWidth` (default 100, 0 = off) wraps assistant prose on wide terminals while code blocks and tables keep the full width.
- Full-screen view: while scrolled up, the last prompt is pinned at the top (click to jump to it) and the jump button counts new messages (`N new ↓`).
- System prompt: a fixed rule to reply in the language the user writes in (constant text, so the cached prefix is unchanged turn to turn).
- Todo tool: the agent keeps a checklist for multi-step work, shown in a panel above the editor (collapsed past 5 items; `/todo` or the tool-output toggle expands it) and saved in the session. One hidden reminder when a run ends with unfinished items (never in plan mode or /review), and the open list is a router signal. `todo.enabled`, `todo.nudge` (on by default).
- `/review [uncommitted|<commit>|<branch>]` and `runkiln review [target] [--fail-on P0|P1|P2|P3]`: a read-only review (only read, grep, find and ls run, in every permission mode) with findings by priority and `file:line`. `--fail-on` exits 2 when a finding at that priority or above is found (for CI). When the model ends the review run with an empty message, RunKiln asks once more, hidden and still read-only.
- `/commit [turn|session|all]`: a conventional commit message from the chore model, shown to edit or confirm; path-limited commits leave the user's other staged files alone. `git.autoCommit: "turn"` commits each file-changing turn (default `"off"`). `git.coAuthor: "Name <email>"` adds a `Co-authored-by` trailer (default empty: no trailer).
- `--worktree [name]`: the session runs in a new git worktree and branch under `.runkiln/worktrees/<name>`; on exit, merge it into the base branch, keep it, or remove it.
- Notifications when a turn ends or an approval or plan waits while the terminal is unfocused: OSC 9 / OSC 777 desktop notifications where supported, else the bell (`notifications: auto|bell|off`). The TUI enables focus reporting (`CSI ? 1004 h`); without it, only turns over 30 s notify.
- Idle compaction: after an idle gap longer than the cache TTL, compact before the next turn when the context is at least `compaction.idleMinTokens` (40,000); `compaction.idleCompact` (on by default).
- Repo map (Aider-style): tree-sitter tags (WASM grammars from `@vscode/tree-sitter-wasm`, regex fallback), PageRank over definition/reference links centered on the files and names the conversation mentions, rendered to a token budget, tags cached on disk by git HEAD and file mtime/size. Exposed as the read-only `repo_map` tool and `/map [tokens] [paths…] [words…]`, never in the system prompt (it would break the prefix cache). **Off by default** (`repoMap.enabled: false`, `repoMap.firstTurnTokens: 0`): on the 22-task bench (r1) it cut turns (glm-low 6.59 → 4.64) but passed fewer tasks (21/22 → 19/22; auto 20/22 → 17/22); r2 after the ranking fixes: glm-low 11/12 → 10/12, auto 11/12 → 11/12 on 12 agentic tasks.
- `router.sessionModel` (default `false`): route only the first request of a session and keep that model and thinking level (failover still switches). Same pass rate as per-request routing on the bench (20/22) and cheaper in the session bench ($0.0034 vs $0.0060), but per-request routing stays the default until it is measured on more sessions.
- `/usage` (also `/cost`, `/stats`, or a click on the footer's cost meter): a full-screen overlay with Overview, Models, Turns, Context and History tabs. Overview: billed total, cache hit rate and what it saved, time to first token, spend by category (main, subagents, chores, router classifier, permission judge) and budgets. Models: per model•thinking pair. Turns: cost, cache, requests and duration per turn with the router's pick and reason. Context: what fills the window. History: spend across saved sessions by day, model and category with a $/day sparkline. `/usage <tab|today|week|month|all>` opens a tab directly. In print mode `/usage` prints every tab as text, or one `{ "type": "usage" }` line with `--mode json`.
- Server-billed costs: RunInfra/OpenRouter `usage.cost` (or `usage.runinfra.cost_microcents`) replaces the catalog estimate for the request (`usage.costSource: "server"`); unbilled decision-model calls are marked estimated. Responses record their time to first token (`ttftMs`). Router decisions are saved as `runkiln.route` session entries.
- Usage ledger `~/.runkiln/agent/usage.jsonl`: one line per billed call of every saved session. `runkiln usage [today|week|month|all] [--since 7d] [--json] [--rebuild]` totals it; `--rebuild` rewrites it from the session files. `RUNKILN_USAGE_LEDGER=0` turns it off.
- Budgets: `budget.session` and `budget.daily` (USD) in settings. A warning at 80%, a confirmation before the next prompt at 100%, never a hard stop.
- Post-edit diagnostics: after each edit/write, the file is checked before and after and only the diagnostics the edit introduced are appended to the tool result (errors first, about 20 lines). Auto-detected checkers (biome/eslint, tsc while fast, ruff or a Python syntax check, gofmt/go vet, cargo check, `node --check`, shellcheck, and a TypeScript syntax fallback through Node's type stripper), per-glob `checks.commands` that pass the permission gate, baselines cached by file content. `checks.enabled` (on), `checks.autoDetect`, `checks.timeoutMs` (4000). An edit that introduces errors counts as a tool error for router escalation. Subagent edits are not checked.
- Verify loop: after a file-changing turn, run the project's tests (detected or `verify.command`) and send condensed failures back as a hidden follow-up, up to `verify.maxRetries` (2), stopping when the same failure repeats; each failure escalates the router within its own turn only. `verify.mode` `ask` (default; the choice is saved per project in `verify.projects`), `auto`, `off`; a project-set command is always confirmed. `/test [off|ask|auto|<command>]`, a footer marker (`✓ tests`, `✗ 3 failing ↻1`), and `--verify` in print mode (exit 1 when tests still fail). A test command that cannot run at all (missing test file or module, unknown command, nothing collected) is reported to the user (`⚠ test command`) and never sent to the model.
- Edit-miss hints: a failed edit shows the closest window with line numbers and a compact diff. Optional `edit.autoRepair` (off) lets the chore model fix `oldText` when one spot is at least 90% similar; applied only if it then matches exactly once inside that window.
- `bench/quality/verify-ab.mjs`: A/B of main vs this pipeline on the 12-repo agentic slice (hidden tests).

- Plan mode (`plan`), as in Claude Code: read-only research (read, grep, find, ls), every write, edit, shell command and other tool blocked; the turn ends with a `## Plan` and a prompt to run it (back to the previous mode), keep planning, or discard it. In `/permissions`, the Alt+M cycle after read & write, `--permissions plan`, and the footer badge `‖ plan · read-only`. Never saved as the default.
- Saved permission rules (`permissions.allow` / `ask` / `deny`, Claude Code syntax: `Bash(npm test:*)`, `Read(.env)`, `Edit(src/**)`, `mcp__x__*`) in global settings, per project in global settings, and ask/deny only in a project's `.runkiln/settings.json` (a project can only tighten). Deny beats ask beats allow; deny applies in every mode, allow-all and plan included. "Always allow in this project" in the approval prompt; `/permissions rules` lists and removes rules (session rules one by one); `/permissions allow|ask|deny <rule> [--project]`.
- `npm run lint` / `npm run format` (biome, now a pinned dev dependency).
- Alt+R (`app.router.cycleMode`) cycles the auto routing mode `auto:low → auto:medium → auto:high` and turns auto on from a manual model; the footer and a status line show the mode. Rebindable in `keybindings.json`, listed in `/hotkeys`, `/help`, the expanded startup help and `/router`, and reserved against extension shortcuts.
- Permission modes `ask`, `read-write` (default), `auto` (needs a router classifier key) and `allow-all`: `/permissions`, `--permissions <mode>` / `RUNKILN_PERMISSIONS`, the `permissions.mode` setting, and Alt+M (`app.permissions.cycle`) to cycle in-session. The footer shows the mode on the pwd line.
- Turn checkpoints with `/undo` and `/rewind`. Before a turn's first edit, write or shell command, RunKiln snapshots the project into a shadow git repository under `~/.runkiln/agent/checkpoints/<session>` (your own `.git`, index and stash are never touched) and backs up each edit/write target, including ignored files and projects without git. `/undo` puts the files back as they were before the last turn that changed them; `/rewind` lists the branch's turns with a per-file diff summary and restores the files, the conversation, or both. Both confirm first, list what will be overwritten, flag files changed outside RunKiln since the last turn and protected files, and only write inside the project. Files over 5 MiB and symlinks are left out. `doubleEscapeAction: "rewind"` makes Esc Esc open `/rewind` (the default stays `tree`); `RUNKILN_CHECKPOINTS=0` turns checkpoints off.
- Per-mode thinking policy in `router.yaml`: `modes.<mode>.min_thinking` (hard floor), `max_thinking` (hard cap, escalation and momentum included) and `trivial_below` (trivial-turn bound). Levels the user pins are not bound.
- Full-screen setup (`runkiln setup`, `/setup`, first run): alternate screen, centered and resize-aware, terminal restored on finish, quit, Ctrl+C or a signal. Welcome with the RK banner, a step indicator, then Key (masked, paste is checked at once, spinner, clear errors), Router classifier, Default model (auto low/medium/high or one manual model), Default thinking, Permissions (`permissions.mode`, the setting `/permissions` writes: `auto` only with a Jev or OpenRouter key, `allow-all`, `read-write`, `ask`), Theme (live preview) and a Review where any step can be reopened. Nothing is saved before Finish. Arrows/Tab, Enter, Esc back, `q`/Ctrl+C with a confirmation. Inline fallback on `TERM=dumb` or `RUNKILN_SETUP_INLINE=1`.
- Router classifier keys: an optional Router step in setup (Jev, OpenRouter with a model id, or skip), a Router section in `/key` (test, replace, remove, switch classifier), and `runkiln login --router jev|openrouter [--stdin]` / `runkiln logout --router`. Keys are checked live and saved to `~/.runkiln/agent/router-keys.json` (0600); `TYPESAFE_API_KEY` / `OPENROUTER_API_KEY` still win.

### Changed

- DeepSeek V4.1 Flash 1017 (`deepseek-v4-1-flash-1017`, $0.15 / $0.60 / $0.01 cached per M, image input) is the default DeepSeek: the chat role, the chore model and the router's DeepSeek pairs, with its own off/low/high curves from a full suite run (340 trials per level: 85.6% / 93.2% / 92.4% / 91.8%, against the old model's 85.0% / 91.5% / - / 90.6%). On the session replay (seeds 1-12) it is 36.5% cheaper with +2.81pp expected pass in low and 40.6% cheaper with +1.40pp in medium, on every seed; 8/8 like the old one on the live slice for 23% less. It also takes images (the old one did not). `deepseek-v4-1-flash` is now an alias (`aliases` in `models.yaml`): settings, `--model` and saved sessions that name it get 1017, and the live listing of the old id is not offered on its own.
- models.yaml: probed efforts, cache and TTFT notes for Qwen3.8 27B, Ornith 1.5 35B and Nemotron 3.5 Lightning 30B (`bench/cache/probes-new-models.md`). None of them joins the router: not cheaper at the same pass rate on the live slice.

- Slash commands: 53 listed down to 37, one per job (`/delegate` and `/subagents` went with subagents). Old names are hidden aliases that still work and say the new name once per session: `/key`, `/login`, `/logout`, `/runinfra` (now `/setup keys`), `/models`, `/scoped-models` (`/setup model`), `/statusline` (`/setup footer`), `/cost`, `/stats` (`/usage`), `/session` (`/status`), `/hotkeys` (`/help`), `/clear` (`/new`), `/exit` (`/quit`), `/clone` (`/fork`). The separate key manager screen is gone; its job is the hub's Keys section. Hints that named the old commands point at `/setup keys` and `runkiln key set`.
- `runkiln login` / `runkiln logout` are hidden aliases of `runkiln key set` / `runkiln key remove` (their `--router` flag still works) and print the new name.
- Setup wizard layout: fixed slots shared with the hub, blank lines that never collapse, a reserved status line, and a body that scrolls with "N more" markers on short windows instead of squeezing. After a key checks out the key step stays with `✓ Key works - N models` and moves on after 1.2 s (Enter moves on at once).
- UI separators: middle dots and em dashes in UI strings are a plain " - " across packages (footer, title, usage, pickers, setup). The footer golden is regenerated.
- Router v3: cache-aware, sticky routing (`quality.cache` in `router.yaml`). RunInfra keeps one prompt cache per (model, thinking) pair on a session, so each pair in the band is priced over the next turns (the miss now, the warm turns after it, the likely miss back) less the failed turns its pass rate avoids, and the warm pair stays unless a clearly better (`clear_gain`, 0.02) or cheaper pair pays for its miss. Inside a tool loop only hard failures leave the warm pair, in one jump. The classifier call is skipped when the warm pair wins for every kind, difficulty and answer length. `modes.<mode>.cache` overrides the pricing per mode; low keeps the warm pair inside its 0.10 band (`clear_gain: 0.10`) and weighs pass rate on a session's first pick (`first_turn_quality`). On the session replay (`bench/router/session-replay.mts`, 12 seeds) against main: medium -2.3% cost and +0.27pp expected pass on the tuning seeds (-1.0% / +0.29pp held out), low -0.5% / +0.31pp (-0.9% / +0.35pp held out). `quality.cache.enabled: false` restores one-turn pricing.
- The tool list and system prompt are frozen for the session, so each request extends the previous one byte for byte and keeps the prompt cache (a scripted-session test checks it).
- Startup: the compile cache is flushed after startup and undici loads on first use.

- `runkiln usage --json`: `since` and `until` are local ISO times with the zone offset (`2026-10-17T00:30:00.000+02:00`) instead of UTC `Z` times, and a new `utcOffset` field sits next to `timeZone` (both resolved from `TZ`, else the OS zone via `Intl`, else UTC).
- The fallback prompt-cache TTL is 900 s (RunInfra's session idle TTL) instead of 5 minutes.
- The footer cost meter reads `$0.0123 - 87% cached` (or `$0.41/$0.50` against a budget); `/cost` is now an alias of `/usage`.
- OpenRouter classifier and auto-permission judge: decision models only, through OpenRouter's Decisions / System One API (`POST /api/v1/systemone`, the same typed questions and probability answers as Jev) instead of a chat model with a JSON schema. Confidence comes from the answer probabilities (a weak allow asks; a task answer under 0.3 top probability falls back for routing). The model list is live (`GET /api/v1/models?output_modalities=decisions`, cached 24 h) and offered as a picker in setup's classifier step, `/key` → Router and `runkiln login --router openrouter --router-model`; chat models are refused. Default `typesafe/jev-1.14` (best of 18 benched decision models on `bench/router` and `bench/permissions`: 99.2% good picks, 63/63 permissions, 0 unsafe). A saved `router.openrouter.model` that is not a decision model (the old default `google/gemini-2.5-flash-lite`) moves to the default at startup with a one-line notice.
- Auto permissions: a local pre-pass runs obvious routine calls (read-only git, project inspection, the project's test/lint/build scripts, ordinary project edits) with no model call; the decision model sees the user's latest request, recent turns and a git summary, answers a structured verdict (decision, risk, category, requested, confidence) and weak answers ask; risky calls still always ask but a confident model deny now blocks them; judging starts while the call is shown, is cached per normalized command, and times out after 4 s (was 8 s). `git stash drop/clear` and `git branch -D` are risky. On the new 63-call eval (`bench/permissions`): Jev 84.1% → 96.8%, OpenRouter 84.1% → 95.2%, 0 unsafe allows.
- Router v2: the `auto` router selects by measured quality curves instead of skill-score bars. Each (model, thinking) pair has a pass rate per task kind (chat, code, algo, math, agentic, terminal) at the bench's easy/medium/hard anchors (`quality` in `router.yaml`, calibrated from the 2026-10-15 quality suite); the router takes the cheapest pair within the mode's band of the best, cache-aware. The classifier asks for the task kind, a bench-calibrated difficulty, follow-up, output length and ambiguity (about half the Jev input tokens of the 80-skill question). Obvious acks and bare follow-ups ("yes do it", "try again") skip the classifier; follow-ups inherit the previous turn; a failed turn (request error, tests still failing, repeated tool errors, "still broken") steps the next turn up a pair, and a good turn resets it. The classifier call starts before the live-catalog refresh. On `bench/router` (118 turns, Jev): 100% acceptable picks vs 77% before, 0% underspend (12.7% before). `selection: scores` keeps the old selector.
- Tool calls the user did not approve no longer count as tool errors for router escalation.

- High mode no longer spends the strongest model and max thinking on trivial turns: a turn whose own difficulty is below `trivial_below` (0.2) takes the cheapest feasible model, with thinking floored at `low` (never off). Non-trivial turns still get the strongest pair, and a cheaper model left warm by a trivial turn no longer sticks (stickiness 0 now means never stick).
- Low mode caps thinking at `low` by default (`max_thinking`); tool-error, failing-test and momentum escalation move to a stronger model instead of a deeper level. Its old `thinking.max_auto: high` is gone (it sat above the cap and never applied); a mode entry that sets `max_auto` above its own `max_thinking` is now rejected.
- The startup header has a RunKiln onboarding line again ("RunKiln picks the model and thinking for each turn: alt+r cycles auto:low/medium/high, /router shows why.", with the bound key) in place of the dropped upstream "Pi can explain its own features" hint.
- Setup no longer asks for chat and title models; it sets the default (code) model. `models.chat` / `models.title` in settings.json still work.
- Removed leftover upstream naming: user-facing text, comments, identifiers, temp-file and log names now say RunKiln. Legacy `PI_*` environment variables are still read as a fallback for their `RUNKILN_*` replacements.
- Dropped the upstream changelog history, which described features and docs RunKiln does not ship. See NOTICE.md for provenance.

### Removed

- Subagents (on main since 0.1.0, never released): the `task` tool, `/delegate`, `/subagents` and the `subagents.*` settings. On the multi-part bench single-agent auto passed 10/10 for $0.009 against 9/10 for $0.037 with subagents, about 2x faster, and a mid-session tool change threw away the prompt cache. Migration: old `subagents` settings and `SubagentStop` hooks are ignored (no error), and `/delegate` or `/subagents` prints a one-line notice. The classifier no longer asks the `parts` question.

## [0.1.0]

- First RunKiln release.
